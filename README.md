# 플랜두씨 다이어리 — 과제 6

계획 → 할 일 → 실행 기록 → 돌아보기 → 다음 계획을 Cloudflare D1 데이터베이스에 저장합니다. 로그인 없이 공개되는 과제용 앱입니다. 모든 방문자가 읽고 쓰고 수정·삭제할 수 있습니다.

## 사용
1. 새 계획에서 기간·우선순위·성공 기준·예상 시간을 저장합니다.
2. 계획의 ‘할 일 추가’로 마감일·태그·예상 시간을 입력합니다. 각 할 일에서 실행 기록과 완료 상태를 별도로 관리합니다.
3. 돌아보기 숫자를 누르면 해당 근거 기록으로 이동합니다. 계획의 ‘돌아보고 다음 계획으로’에서 개선점을 다음 계획에 넘깁니다.

집계 대상은 선택한 계획의 미삭제 할 일입니다. 기간은 할 일 마감일에 적용합니다. 예상 시간은 할 일 예상 시간 합계이고 실제 시간은 해당 실행 기록 합계입니다. 지연은 서울 기준 오늘 이전 마감이면서 미완료인 할 일입니다. 막힘은 이유가 있는 할 일의 고유 개수입니다.

계획 수정 전 값은 별도 이력에 남습니다. 완료 표는 할 일 ID를 기본키로 사용하며 실행 기록은 요청 UUID를 기본키로 사용합니다. 중복 요청은 중복 기록을 만들지 않습니다. 회고와 다음 계획은 하나의 트랜잭션으로 저장됩니다.

## 소스와 데이터
- 데이터 구조 및 날짜 규칙: `contracts/pds-schema-v2.json`
- 원본 스키마와 마이그레이션: `db/schema.ts`, `drizzle/`
- 입력 검증·저장 API: `app/api/diary/route.ts`
- 집계 함수: `lib/diary.ts`
- 공개 소스 다운로드: 사이트의 `/source.zip`
- 전체 데이터 내보내기: 화면 상단 버튼(JSON)
- 기존 v1 데이터는 `entries`에 보관하며 내보내기에 포함됩니다. v2 집계에는 포함하지 않습니다.
- 소스 ZIP에는 데이터베이스, 로컬 실행 자료, Git 자격증명, 환경 비밀값을 넣지 않습니다.

## 로컬 실행
Node.js 22.13 이상에서 `npm ci`, `npm run build`를 실행합니다. 로컬 D1에 `drizzle/`의 SQL을 파일 순서대로 최초 1회 적용한 뒤 `npm run start`를 실행합니다.

```
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_charming_bedlam.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0001_mute_ego.sql
```

`node scripts/verify-local.mjs`는 실행 중인 localhost:8787에 검증용 자료를 생성합니다. 운영 데이터로 사용하지 않습니다. 로컬 DB와 운영 DB는 별개입니다.

## 확인 방법 4줄
어디로 가나요: 결과물 주소의 다이어리 첫 화면으로 이동합니다.
세 단계 안에 무엇을 하나요: 기존 할 일의 실행 기록 저장 → 새로고침 → 돌아보기의 실제 시간 숫자를 누릅니다.
무엇이 보이면 통과인가요: 저장한 기록의 ID·시각·분 값이 유지되고, 집계의 근거 기록에 해당 실행이 나타납니다.
안 될 때는 무엇이 보이나요: 조회·저장 오류 안내와 다시 불러오기 버튼이 나타나며, 저장 실패 시 입력 창의 내용이 유지됩니다.

## 제출 전 사용자 작성
실제 계획 1개, 할 일 5개 이상, 실행 기록 3개 이상을 입력하고 회고와 다음 계획까지 연결하세요. 기존 로컬 개인 기록은 사용자의 선택에 따라 공개 서버로 옮기지 않았습니다.

AI와 내 판단은 사실에 맞게 사용자 본인이 마무리해야 합니다. AI에게 맡긴 일은 화면·데이터 구조·저장·검증·배포 작업입니다. 사용자가 직접 판단한 일은 기존 기록을 로컬에 보관하고 새 기록을 직접 입력하기로 정한 것입니다. AI 제안을 따르지 않은 사례 또는 없었던 이유는 사용자가 직접 작성하세요.
